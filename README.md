# Claude Code 个人工作系统

不是「怎么用 AI 写代码」，是**怎么让 AI 按我的方式来**。

这套配置把和 AI 协作的经验固化成三层结构：**指令（它该怎么做）→ 护栏（它不能做什么）→ 记忆（它该记住什么）**。目的是让每一次新对话都从上次的水平开始，而不是从零。

---

## 三层结构

```
CLAUDE.md          指令层 —— 13 条红线，定义行为边界
hookify.*.local.md 护栏层 —— 3 条自动规则，在关键节点拦截或告警
MEMORY.md + gotchas 记忆层 —— 持久化记忆，渐进式加载（本仓库不含，见下）
```

---

## 一、指令层：CLAUDE.md

23 行，13 条硬规则。核心不是「多写规则」，而是**只写会反复犯的错**。

### 规则分三类

**① 工作流的入口约束**
```
1. 行动前先停 5 秒想任务本质 → 查可用技能 → 挑最合适的组合
5. 禁擅自改文件名 / 目录名 / 属性
10. 制作前先写工作计划 → 用户确认
```
> 本质：AI 最大的浪费不是写错代码，是**没想清楚就开始动手**。

**② 失败与资源的止损机制**
```
6. 任何工具连续失败 2 次 → 停，重评策略，换方法
7. 搜索先定位领域公认好站 → 站内直搜 → 不撒网、不挨个试
4. 禁手写临时脚本 → 技能不覆盖 → 找现成方案 → 再手写
```
> 本质：**给失败设硬上限**。连续失败 2 次还在硬试，是 AI 最典型的失控模式。

**③ 判断「该问还是该做」**
```
11. 纯技术问题 → 直接给最优方案；需求 / 效果方向 → 必须先问
12. 完成任务后必须自我验证 → 不能只声明成功
9.  产出统一保存到固定目录
13. 技能随用随关 —— 每阶段只加载所需技能，不保留上一阶段上下文
```
> 本质：**区分「执行」和「决策」**。执行要果断，决策要确认。规则 13 是上下文管理 —— 上下文越干净，判断越准。

### 一条元规则

```
同一错误犯 2 次 → 才加进规则；不预加规则 → 避免过度约束
```

**规则是债务。** 每加一条，AI 的决策空间就窄一分。所以只有真正犯过两次的错才值得写成规则 —— 这条本身比那 13 条更关键。

---

## 二、护栏层：3 条 hook 规则

CLAUDE.md 是「建议」，hook 是「强制」。软约束靠提示词，硬约束靠 hook。

| 规则 | 触发点 | 动作 | 拦什么 |
|---|---|---|---|
| `block-dangerous-ops` | 执行 bash 前 | **拦截** | `rm -rf /`、`rm -rf ~`、`git push --force origin main` |
| `config-edit-warning` | 编辑文件时 | **告警** | 改 `settings.json` / `CLAUDE.md` / `MEMORY.md` / `gotchas.md` |
| `verify-before-stop` | 任务收尾时 | **告警** | 没跑测试 / 没截图 / 没确认产出就宣布完成 |

**设计取舍**：只有真正不可逆的操作用「拦截」，其余用「告警」。全拦截会让人绕过规则，全告警等于没有规则。

`config-edit-warning` 的告警文案里有一句自检要求：

> 改后做一次自我检查：这个改动会让**下次的我**更聪明，还是更困惑？

## 三、记忆层：为什么这个仓库里没有

我的记忆文件（`MEMORY.md` + `gotchas.md`）里包含**个人环境信息**（本机路径、网络配置、进行中的项目），不适合公开，因此未包含在本仓库。

但设计思路可以说：

- **渐进式加载** —— 索引文件只放一行摘要，详细内容拆到独立文件，需要时才读
- **索引控制在 200 行以内** —— 索引本身会占上下文，太长就失去意义
- **gotchas 优先** —— 实际犯过的错排在理论规则前面
- **和指令层共用同一条元规则**：同一错误犯 2 次才写进去

## 怎么用

把需要的文件复制到你的 `~/.claude/` 目录：

```bash
git clone https://github.com/<your-name>/claude-code-workflow.git /tmp/ccw
cp /tmp/ccw/CLAUDE.md ~/.claude/
cp /tmp/ccw/hookify.*.local.md ~/.claude/     # 需要 hookify 插件
```

**别照抄**。这 13 条是我踩过的坑，你的坑不一样。正确用法是：跑一段时间 → 记录重复犯的错 → 只把犯了 2 次的写进规则。
